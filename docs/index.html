cgmlst-dists-rs

Ultra-fast pairwise cgMLST Hamming distance matrix from chewBBACA allele-call tables. A Rust reimplementation of cgmlst-dists, with a SIMD distance kernel and multi-core everything.

GitHub crates.io Docker (ghcr.io) cgmlst-dists-py

Install

Docker

docker pull ghcr.io/genpat-it/cgmlst-dists-rs

Debian slim, portable AVX2 build (x86-64-v3).

crates.io

cargo install cgmlst-dists-rs

Add RUSTFLAGS="-C target-cpu=native" for AVX-512.

From source

git clone https://github.com/genpat-it/cgmlst-dists-rs
cd cgmlst-dists-rs
RUSTFLAGS="-C target-cpu=native" \
  cargo build --release

Usage

cgmlst-dists -i chewbbaca.tab -o distances.tsv
cgmlst-dists -i chewbbaca.tab -m lower-tri > dist.tsv
cgmlst-dists -i chewbbaca.tab -o distances.tsv.gz     # parallel gzip

docker run --rm -u "$(id -u):$(id -g)" -v "$(pwd):/data" \
  ghcr.io/genpat-it/cgmlst-dists-rs -i /data/chewbbaca.tab -o /data/distances.tsv

Distance = number of loci where the two alleles differ and both are present. A leading INF- is stripped; chewBBACA classes (LNF, PLOT3, ASM, …), -, empty and 0 are missing. Full option list in the README.

chewBBACA hashed profiles

Hashed profiles store CRC32 hashes as allele ids, up to 4 294 967 295. Alleles are read as 64-bit integers, so every hash is kept. Earlier releases (≤ 0.1.2) read alleles as 32-bit signed integers and silently treated every hash above 231 as missing — about half of the calls.

Benchmarks

Full matrix, same output (md5-identical) from both tools. 80-core x86-64 with AVX-512; tseemann cgmlst-dists 0.6.0 built with its Makefile (-Ofast -fopenmp), run with -j set to the core count and -x 100000 so it computes the same thing. Best of three.

tseemann also cannot read the 6 785-locus wgMLST table from the same study: its 100 000-character line buffer is shorter than the header.

Why it is fast

  • SIMD kernel. The inner loop (differ && both present) is written so LLVM vectorizes it: 16 loci per AVX-512 instruction.
  • Half the work. Only the upper triangle is computed and stored; the output mirrors it.
  • Parallel everywhere. Parsing, distances (rayon work stealing over the triangular workload), row formatting and optional gzip all use every core.
